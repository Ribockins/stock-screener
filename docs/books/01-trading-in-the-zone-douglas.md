## Главная идея

Проблема трейдера — не отсутствие стратегии, а **нестабильное исполнение** из-за страха, надежды, жадности и непринятия неопределённости.

Трейдер должен уметь:

1. Не бояться войти (когда правила говорят «да»).
2. Не бояться закрыть убыток.
3. Не мстить рынку.
4. Не ломать правила после серии убытков.
5. Не становиться самоуверенным после серии прибылей.
6. Думать **вероятностями**, а не «я прав / неправ».

---

## Ключевые идеи (для GEM / EDGE)

### 1. Рынок не обязан подтвердить один сигнал

**Score / PREMIUM / Trade OK** = статистическое преимущество, **не гарантия** одной сделки.

- Неправильно: «Система дала сигнал — рынок обязан».
- Правильно: «Есть edge на серии; исход этой сделки неизвестен».

### 2. Серии сделок, не одна сделка

| Масштаб | Смысл |
|---------|--------|
| 1 сделка | шум |
| 20 сделок | картина |
| 50–100 | статистика системы |

Не менять GEM после **одного** ложного Ruby/Emerald — только после **журнала** (win rate, avg R, drawdown).

### 3. Риск принят до входа

Вход только с заранее известными: stop, TP/цель, invalidation, % риска.

В GEM: чеклист пункт **risk**; без него — не **CONFIRMED**.

### 4. Не торговать «правоту»

EDGE отбирает ситуации, не доказывает гениальность.

### 5. Consistency важнее «идеального» анализа

Пропуски, ранние входы, revenge size, отключение системы после 2 лоссов — убивают edge.

### WARNING vs CONFIRMED (Douglas: Signal ≠ Trade)

| Tier | Значение |
|------|----------|
| **WAIT** | Нет edge / не смотреть |
| **WARNING** | Кандидат (setup, ARMED) — **не** эмоциональный вход |
| **CONFIRMED** | Trade OK + GEM/entry tier — можно исполнять по плану |

## EDGE Discipline Protocol (кратко)

1. Сигнал появился → 2. Score / MTF → 3. Направление → 4. **WARNING** — ждём trigger → 5. Вход по правилу → 6. Риск известен → 7. План не менять → 8. Запись в журнал → 9. Оценка **серии**.

Полная версия: `docs/edge-discipline-protocol.md`.

---

## Правила после убытков (не менять код сразу)

- После 2 убытков подряд — **не** увеличивать размер.
- После 3 убытков подряд — стоп на день (см. `config/discipline.json`).
- Изменение логики GEM — только после **серии** в журнале, не после одного сигнала.
