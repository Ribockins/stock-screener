# Research engine

Сейчас рабочий набор — **NG** и **WTI**. Котировки: Yahoo `NG=F` и `CL=F`, непрерывный фронтальный контракт. Сессия считается по Нью-Йорку: Asia 18:00–03:00, Europe 03:00–09:00, US 09:00–17:00, пауза 17:00–18:00. Шаг цены NG — 0.001, WTI — 0.01.

Исследовательский конвейер для одного инструмента. EURUSD остаётся в коде журнала, но предложение направления по умолчанию считает только NG и WTI. Он проверяет бары, задаёт исход close-to-close, ведёт журнал и считает калибровку. Он не выставляет заявки и не публикует вероятность, пока в корзине меньше `min_samples` уже известных исходов.

Cloud Agent не видит `C:\SierraChart\Data\...`. Файл должен оказаться там, где запускается эта команда: на машине с экспортом Sierra, на сервере, куда collector его копирует, или в приватном хранилище, которое читает тот же процесс.

## Что делает каждый запуск

1. Читает CSV Sierra (`Date`, `Time`, `Open`, `High`, `Low`, `Close`/`Last`, при желании `Volume`, `BidVolume`, `AskVolume`).
2. Отбрасывает незакрытый бар, обрыв строки и невалидный OHLC.
3. Не перезаписывает уже сохранённый бар. Другая цена на ту же метку времени — конфликт, в базе остаётся первая запись.
4. Считает признаки только из баров, которые уже закрыты к моменту решения.
5. Пишет прогноз один раз. Повторный запуск ту же строку не меняет.
6. Когда бар горизонта появился, дописывает факт. Пропуск не интерполируется: строка становится `unavailable`.

Вероятность в отчёте — это доля прошлых UP/DOWN/FLAT в корзине `сессия|trend_*`. Сессия берётся по концу бара в `Europe/London`: Asia 00:00–07:00, London 07:00–16:00, New York 13:00–22:00, пересечение London/NY отдельно. Trend — знак `(close - SMA) / ATR` относительно полосы `0.25`. ATR здесь — простое среднее true range, не Wilder и не формула Sierra, пока сверка бар-в-бар не сделана.

Аналоги считаются отдельно и не смешиваются с этой частотой. События и внешние ряды (`ROTOR`, `GEM`, `VECTOR`, DXY) попадают в снимок только если их время доступности не позже решения. Формулы ROTOR/GEM/VECTOR в этот пакет не переносились.

## Правило исхода

Для горизонта H берётся close бара, который заканчивается ровно через H после решения.

- `UP`, если изменение больше `flat_band_pips` (по умолчанию 1 pip, pip = 0.0001)
- `DOWN`, если изменение меньше `-flat_band_pips`
- `FLAT` иначе

Это изменение закрытия, не максимальное благоприятное движение и не диапазон «+18–32 pips». Квантили q25/q75 печатаются только вместе с опубликованной частотой и подписаны как ближайший ранг прошлых движений корзины.

Горизонты по умолчанию: 1, 3, 6 и 24 часа. Горизонт, который не делится на размер бара, пропускается.

## Команды

Первый проход по уже накопленному файлу — реконструкция, не forward-test:

```bash
python -m research_engine run \
  --csv /path/to/EURUSD.csv \
  --db data/research/eurusd.sqlite \
  --timeframe 1h \
  --source-timezone UTC \
  --backfill
```

Если файл минутный, рабочий ряд задаётся отдельно. Неполная последняя корзина выбрасывается:

```bash
python -m research_engine run \
  --csv /path/to/EURUSD_M1.csv \
  --timeframe 1m \
  --resample 1h \
  --backfill \
  --db data/research/eurusd.sqlite
```

Дальше тот же `run` без `--backfill` пишет только новое последнее решение. Планировщик на машине с файлом может вызывать его раз в час, в 07:00 и 13:00 London и вечером. `--mode` только подписывает триггер: `hourly`, `london-open`, `us-open`, `macro`, `daily`.

После того как горизонт прошёл:

```bash
python -m research_engine learn --db data/research/eurusd.sqlite
```

`learn` ничего не пересчитывает в вероятностях. Он дописывает факты и печатает Brier и log loss отдельно для forward-test и для backfill. Перекрывающиеся часовые прогнозы там же помечены как зависимые.

Пример файла только показывает колонки: `research_engine/examples/eurusd_sample.csv`. На трёх барах окно ATR не набирается, и команда обязана закончиться без частоты.

Календарь и внешние сигналы — отдельные CSV. Строка события участвует только если `available_at` не позже решения. Образец webhook `research_engine/examples/webhook_event.json` — это повод запустить `run`, а не готовый сценарий.

## Сила направления раз в два часа

`propose` без символа считает NG и WTI. Слои идут в одном порядке: геополитика, фундамент, техника, свечи. В среднее входят только слои, у которых есть чтение. Знак задаётся отдельно: `ng_sign` и `wti_sign`. `+1` — в пользу роста этого контракта, `-1` — в пользу снижения. Один и тот же заголовок может толкать газ и нефть в разные стороны. Движок сам не выводит знак из сюрприза цифры.

Слот — чётный час UTC. Задержка в минуту и дольше нормальна. Если с конца слота прошло больше 2 часов 15 минут, сила для текущего цикла не публикуется.

```bash
python -m research_engine sources
python -m research_engine propose --source yfinance --events research_engine/examples/events_signed_sample.csv
python -m research_engine propose --source yfinance --symbol NG
```

Собрать можно CSV Sierra по одному контракту, часовые `NG=F` и `CL=F` через Yahoo, и размеченный CSV событий. TradingView в скринере к этой силе не подключён. Веб-поиск в число не входит: у заголовка нет версии на момент решения.

## Чего здесь нет

Cursor Automation может по расписанию или webhook вызвать отчёт и пересказать журнал. Она не должна быть процессом, который раз в час читает локальный диск Sierra и сама назначает вероятность. Для пропуска запуска, повтора и блокировки файла нужен обычный процесс рядом с данными.

Пока журнал forward-test не накоплен, отчёт прямо пишет, что вывода о калибровке нет. Смена `model_version` или полосы FLAT создаёт новые строки и не затирает старые. Чтобы пересчитать ту же версию на тех же данных, нужна новая база.

Следующий инструмент подключается тем же каркасом после того, как для EURUSD отдельно проверены поставщик данных, сессия, pip и смысл объёма. Объём по умолчанию помечен `unspecified`.
